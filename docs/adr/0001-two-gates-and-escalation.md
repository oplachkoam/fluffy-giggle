# 0001 — Обезличивание в два гейта с эскалацией на человека

| | |
|---|---|
| **Статус** | Принято |
| **Дата** | 2026-11-03 |

## Контекст

Сильной модели нельзя показывать персональные данные. Детерминированные детекторы ловят форму (номера, даты, e-mail), но не смысл («дочь главврача районной больницы»); модель ловит смысл, но ненадёжна и может ходить по кругу.

## Варианты

- **A.** Только детерминированный детектор.
- **B.** Только модель-анонимайзер.
- **C.** Два гейта подряд: детектор, затем модель до N проходов; если модель продолжает находить — стоп и оператор.

## Решение

C. Гейт 1 — регулярки с контрольными суммами и эвристика ФИО. Гейт 2 — слабая модель возвращает список спанов в JSON, замену делает код, таблица соответствий одна на оба гейта. Лимит три прохода; стоп по пустому списку; непустой список после последнего прохода или не убывающий счёт — статус `needs_review`. Ошибка модели и битый JSON считаются непустым списком. Гейт 2 только добавляет замены, снять найденное гейтом 1 не может.

## Почему

A пропускает контекст, B нестабилен и неотладим. В C каждый слой закрывает слепое пятно другого, а предел проходов превращает зацикливание в явное состояние, которое видно оператору.

## Последствия

- Плюс: полнота выше любого из слоёв; трасса показывает, кто что нашёл.
- Минус: до трёх лишних вызовов модели на документ; ложные срабатывания модели оборачиваются эскалациями.
- Долг: обратная подстановка ставит именительный падеж.
