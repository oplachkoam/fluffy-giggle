# 0002 — Граница приватности логическая: одна функция вызова облака после egress

| | |
|---|---|
| **Статус** | Принято |
| **Дата** | 2026-11-03 |

## Контекст

В прототипе все модели — внешние endpoint'ы. Реальной локальной модели нет, поэтому нужен механизм, который делает границу проверяемой, а не декларативной.

## Варианты

- **A.** Сетевой egress-прокси с DLP.
- **B.** Одна функция в коде, через которую проходит любой вызов сильной модели, с проверкой payload перед отправкой.
- **C.** Проверка на совести каждого места вызова.

## Решение

B. `runpipeline.callCloud` — единственный путь к `Models.Cloud`. Перед вызовом `Egress` ищет в payload все формы из vault, числовые значения без разделителей и срабатывания детекторов гейта 1 (кроме дат). Находка записывается шагом `egress:blocked`, вызов не делается. Отправленные payload копятся и после запуска сверяются с канарейками фикстуры.

## Почему

A — отдельный компонент, не нужный тестовому заданию; C не проверяется тестом. B покрывается unit-тестом «сильная модель не вызывается, если черновик содержит значение из vault» и переносится в реальную систему как место, где встанет прокси.

## Последствия

- Плюс: утечка проверяется двумя независимыми способами — гейтом до отправки и канарейками после.
- Минус: строгий egress блокирует совет при любой находке, качество падает; доля блокировок видна в бенчмарке.
