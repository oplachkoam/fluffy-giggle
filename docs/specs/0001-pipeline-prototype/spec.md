## Зачем

Показать механику: вход с ПДн обезличивается двумя гейтами, сильная модель видит только «тень» задачи, слабая финалит, а оператор видит каждый шаг и что именно ушло в облако. Все модели — внешние endpoint'ы, граница приватности логическая. Решения — в [clarify.md](clarify.md).

## Термины

| Термин | Значение |
|---|---|
| **Сторона** | `local` — слабая и vision-модели, `cloud` — сильная, `system` — код, `placebo` — подставной совет |
| **Vault** | Таблица «каноническое значение → плейсхолдер → все встреченные формы», живёт в запуске |
| **Канарейка** | Значение ПДн кейса фикстуры, заранее известное; ищется в payload cloud-шагов |

## Вне охвата

- Реальные локальные модели, сетевой egress-прокси, аудит, квази-идентификаторы.
- Best-of-N, bbox на картинке, рукописный текст.
- Многопользовательность, роли, сессии.

## Пользовательские истории

- **US-1.** Как оператор, я хочу отправить текст или скан претензии и увидеть по шагам, что система сделала и что ушло в облако.
- **US-2.** Как оператор, я хочу вмешаться, когда система не уверена, что ПДн вырезаны.
- **US-3.** Как оператор, я хочу прогнать набор кейсов в трёх режимах и увидеть, даёт ли adviser выигрыш без утечек.

## Функциональные требования

### Запуск — `POST /v1/runs`

- **FR-1.** КОГДА оператор отправляет текст или изображение PNG/JPEG до 10 МБ и режим adviser `off|on|placebo`, СИСТЕМА ДОЛЖНА создать запуск `queued`, сохранить вход и выполнить пайплайн в фоне; ответ `201` с запуском.
- **FR-2.** ЕСЛИ входа нет, изображение не PNG/JPEG или больше 10 МБ, режим неизвестен, ТОГДА `422`.
- **FR-3.** КОГДА передан `case_id`, СИСТЕМА ДОЛЖНА взять вход кейса фикстуры и запомнить его канарейки.

### Пайплайн

- **FR-4.** Каждый шаг ДОЛЖЕН записываться в `steps`: порядок, вид, сторона, статус `ok|failed|blocked|skipped`, время, модель, токены, вход, выход, ошибка; запись публикуется событием `step`.
- **FR-5.** Изображение → шаг `vision` на `LLM_VISION`: транскрипция текста. Изображение не уходит никакой другой модели.
- **FR-6.** Шаг `gate1`: детекторы кода — телефон, почта, паспорт, СНИЛС и ИНН с контрольной суммой, карта по Луну, счёт из 20 цифр, дата, ФИО по отчеству, инициалам и словарю имён, адрес по `г./ул./д.`. Находки заменяются `[TYPE_n]`, одно каноническое значение — один плейсхолдер.
- **FR-7.** Шаг `gate2` (до трёх проходов, каждый — отдельный шаг): слабая модель получает текст и список плейсхолдеров, возвращает JSON-список спанов `{text, type, canonical}`; код заменяет и пополняет vault. Стоп по пустому списку. Таймаут, ошибка и битый JSON считаются непустым списком.
- **FR-8.** ЕСЛИ после третьего прохода список не пуст или не короче предыдущего, ТОГДА статус `needs_review`, находки последнего прохода сохраняются, пайплайн останавливается.
- **FR-9.** Шаг `draft`: слабая модель на обезличенном тексте возвращает карточку `{category, subject, amount_range, event_period, requested_action, summary}` и черновик ответа.
- **FR-10.** Шаг `egress` перед каждым вызовом сильной модели: все формы из vault, числовые значения без разделителей и детекторы FR-6 по payload. Находка → шаг `blocked`, вызов не делается, итог adviser `blocked`.
- **FR-11.** Шаг `advise`: режим `on` — сильная модель получает карточку, черновик и рубрику, возвращает до пяти правок; `placebo` — три правки из фиксированного списка общих замечаний, выбранные по seed запуска, сторона `placebo`; `off` — шаг `skipped`.
- **FR-12.** Шаг `finalize`: слабая модель применяет правки к черновику; без правок финал равен черновику.
- **FR-13.** Шаг `judge`: сильная модель через egress ставит 1–5 обезличенному финалу по рубрике; при блокировке оценки нет.
- **FR-14.** Шаг `reidentify`: плейсхолдеры заменяются каноническими значениями; результат — ответ оператору; статус `done`.
- **FR-15.** ЕСЛИ вызов модели упал после ретраев SDK, ТОГДА шаг `failed`, запуск `failed` с причиной.
- **FR-16.** КОГДА запуск из фикстуры завершён, СИСТЕМА ДОЛЖНА посчитать канарейки в payload cloud-шагов и сохранить число в запуске.

### Проверка оператором — `POST /v1/runs/{id}/review`

- **FR-17.** `continue` — шаг `review`, пайплайн идёт дальше с текущего текста; `finish_without_advisor` — adviser и судья пропускаются. Не `needs_review` → `409`.

### Чтение

- **FR-18.** `GET /v1/runs` — от новых к старым, по 50, курсор `before`; `GET /v1/runs/{id}` — запуск с шагами и vault; `GET /v1/runs/{id}/image` — исходное изображение.
- **FR-19.** `GET /v1/events` — SSE с событиями `run`, `step`, `benchmark`.

### Бенчмарк и фикстура

- **FR-20.** `POST /v1/benchmarks` — все кейсы в трёх режимах, `PIPELINE_CONCURRENCY` параллельно; `GET /v1/benchmarks/{id}` — прогресс и сводка по режимам: запусков, средний балл, утечки, эскалации, ошибки; `GET /v1/benchmarks` — список.
- **FR-21.** `GET /v1/cases` — кейсы фикстуры: id, заголовок, есть ли изображение, число канареек.

### Аутентификация

- **FR-22.** `/v1/*` требует `Authorization: Basic` с `AUTH_LOGIN`/`AUTH_PASSWORD`, сравнение за постоянное время; `401` без `WWW-Authenticate`. `/health` и SPA открыты. `GET /v1/auth/me` → `{login}`.

### Интерфейс

- **FR-23.** `/login`: форма, креды в localStorage; `401` стирает их и уводит на `/login`.
- **FR-24.** `/` «Новый запуск»: текст или изображение, выбор кейса фикстуры, режим; после отправки — страница запуска.
- **FR-25.** `/runs/{id}`: статус, режим, итог adviser, оценка, канарейки; лента шагов с бейджем стороны, статусом, длительностью, моделью, токенами, раскрытием входа и выхода; подсветка ПДн по типам; кнопки FR-17 при `needs_review`; финал с переключателем «обезличенный / для оператора». Обновление по SSE.
- **FR-26.** `/runs`: таблица, «Показать ещё».
- **FR-27.** `/benchmark`: запуск, прогресс, сводка по режимам, список запусков.
- **FR-28.** Светлая и тёмная темы, ширины 1280 и 360.

## Нефункциональные требования

## Известные пробелы

1. Обратная подстановка ставит именительный падеж: «ответ Иванов» вместо «Иванову».
2. Судья и adviser — одна модель; смещение компенсирует плацебо-режим.
3. Слабая модель иногда помечает суммы как ПДн; это лишние плейсхолдеры, не утечка.
4. Номера полисов ловит регулярка «три буквы и десять цифр»; другие форматы договоров ждут гейт 2.
5. Модели выдумывают телефоны и почту компании; промпты это запрещают, egress всё равно блокирует вызов, если выдумка прошла.
