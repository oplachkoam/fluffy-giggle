# 0001 — уточнения

Только итог: вопрос, принятый ответ, затронутые требования. Ссылки на FR появятся вместе со спекой.

## Репозиторий и сборка

- **Q-1.** Имя? — `fluffy-giggle` везде: модуль `fluffy-giggle/core`, бинарь, образ.
- **Q-2.** DI? — uber-fx, граф собирается в `bootstrap`, проверяется `fx.ValidateApp`.
- **Q-3.** Телеметрия? — Только slog. OpenTelemetry не подключается, наблюдаемость живёт в UI.
- **Q-4.** Аутентификация? — Логин и пароль из env (`AUTH_LOGIN`, `AUTH_PASSWORD`), механизм — Q-42.
- **Q-5.** SQLite без CGO? — `modernc.org/sqlite`.
- **Q-6.** Запросы? — sqlc с engine `sqlite`, `make generate`, сгенерированное коммитится.
- **Q-7.** Миграции? — Встроены в бинарь, накатываются на старте. Отдельного `cmd/migrate` нет.
- **Q-8.** Путь к базе? — `SQLITE_PATH`; в контейнере `/data/app.db`, локально `core/data/app.db`.

## CI и Docker

- **Q-9.** Триггеры? — PR и push в `main`: lint и test. Docker build + push: `main` и теги `vX.Y.Z`. Теги образа: `sha`, `latest` на `main`, версия на теге.
- **Q-10.** Образ и секреты? — Yandex Container Registry: `cr.yandex/<registry>/fluffy-giggle`; переменная `YC_CR_REGISTRY_ID`, секрет `YC_SA_JSON_KEY` (вход `json_key`).
- **Q-11.** Платформы? — Только `linux/amd64`.
- **Q-12.** Runtime-образ? — alpine с ca-certificates и tzdata.
- **Q-13.** Джобы? — Один workflow, джобы lint, test, docker, без фильтров по путям.

## Хранение и данные

- **Q-14.** Схема? — Таблицы `runs` и `steps`, payload шагов в JSON.
- **Q-15.** Сырые данные? — Хранится всё, включая исходный текст и vault; в UI помечено как локальная сторона.
- **Q-16.** Картинки? — Блобом в SQLite, лимит 10 МБ.
- **Q-17.** Синтетика? — Фикстура из 20 кейсов в репозитории с известными канарейками, кнопка «прогнать набор» в UI.

## LLM

- **Q-18.** SDK? — `openai/openai-go`.
- **Q-19.** Конфиг моделей? — Три блока `LLM_LOCAL_*`, `LLM_VISION_*`, `LLM_CLOUD_*`: base URL, ключ, модель, таймаут, число ретраев. Local и vision — псевдолокальная сторона, cloud — облачная.
- **Q-20.** Провайдеры? — Провайдер уровня OpenRouter. Local — какой-нибудь Qwen, vision — псевдолокальная OCR-модель средней мощности, cloud — gpt-6. В `.env.example` плейсхолдеры, реальные значения в `.env`.
- **Q-21.** Прогресс запуска? — SSE по шагам.
- **Q-35.** Ошибки LLM? — Простые ретраи по кодам ответа средствами SDK, число ретраев в env. После них шаг падает, запуск получает статус «ошибка» с причиной в трассе.

## Пайплайн

- **Q-22.** Роль сильной модели? — A, критик: слабая пишет черновик, сильная даёт правки, слабая финалит. Best-of-N не делается.
- **Q-23.** Вход слабой модели? — Обезличенный текст после двух гейтов; обратная подстановка один раз в конце.
- **Q-24.** Payload сильной модели? — Карточка с обобщёнными полями + обезличенный черновик.
- **Q-25.** Выходы? — Карточка (категория внутри) и проект ответа.
- **Q-26.** Гейт 1? — Регулярки с контрольными суммами (паспорт, СНИЛС, ИНН, карта, телефон, почта, счёт, даты) и эвристика ФИО по отчеству и заглавным. Сторонних NER нет, остальное ловит гейт 2.
- **Q-27.** Плейсхолдеры? — `[PERSON_1]`, `[PHONE_1]`; типы PERSON, PHONE, EMAIL, PASSPORT, SNILS, INN, CARD, ACCOUNT, ADDRESS, DATE, ORG, OTHER.
- **Q-28.** Гейт 2? — Слабая модель возвращает JSON-список спанов, код заменяет. До трёх проходов; стоп по пустому списку или если список не уменьшается. Таймаут и битый JSON считаются непустым списком.
- **Q-29.** Эскалация? — Статус «нужна проверка», кнопки «это не ПДн, продолжить» и «завершить без adviser».
- **Q-30.** Egress-проверка? — Перед каждым вызовом сильной модели: значения vault и регулярки по payload. Находка блокирует вызов, запуск завершается без adviser с пометкой.
- **Q-31.** Режимы? — Adviser выкл, вкл, плацебо, все три сразу.
- **Q-32.** Судья? — Сильная модель, 1–5 по рубрике на обезличенный финал, в каждом запуске, виден в трассе.
- **Q-33.** Бенчмарк? — В первой версии, последним пунктом: прогон фикстуры в трёх режимах, сводка: средний балл, утечки по канарейкам, эскалации.
- **Q-34.** Картинка? — Vision-модель возвращает транскрипцию, дальше как текст. Без bbox. Картинка в сильную модель не уходит.

## UI

- **Q-36.** Экраны и каркас? — «Новый запуск», «Запуск», «Запуски», «Бенчмарк»; сайдбар слева.
- **Q-37.** Трасса? — Вертикальная лента шагов: бейдж «локально / облако», статус, длительность, модель, раскрывающиеся вход и выход, ПДн подсвечены по типам.
- **Q-38.** Темы и язык? — Светлая и тёмная с кнопкой, интерфейс на русском.

## Документация и тесты

- **Q-39.** Диаграммы? — Блоки mermaid внутри `.md`.
- **Q-40.** Состав docs? — `AGENTS.md` в корне, `core/`, `web/`; `docs/architecture/overview.md`; ADR на ключевые решения; спека 0001. Исследование архитектуры (PDF) в репозиторий не входит: это не документация, а материал к заданию.
- **Q-41.** Тесты? — Go unit на моках, табличные тесты анонимайзера и egress, LLM-клиент на httptest, `fx.ValidateApp`; web vitest + testing-library через `stubApi`. Интеграционных нет.

## Дополнение

- **Q-42.** Сессия? — HTTP Basic через собственную форму: логин и пароль в localStorage, заголовок `Authorization: Basic`; сервер отвечает 401 без `WWW-Authenticate`, чтобы браузер не показывал свой диалог. Сессий на сервере нет.
- **Q-43.** Ключи для сквозной проверки? — Выдаёт оператор, кладутся в `core/.env`.
- **Q-45.** Думающие модели? — У `LLM_<ROLE>_` есть `DISABLE_THINKING` (шлёт `chat_template_kwargs.enable_thinking=false`) и необязательная `TEMPERATURE`; без неё параметр не отправляется, потому что сильная модель принимает только значение по умолчанию.
- **Q-44.** Фикстура? — Двадцать писем пишутся руками, ПДн подставляет детерминированный генератор, пять писем отрендерены в PNG из того же текста.
